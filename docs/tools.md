# Data tools (`tools/`)

- **Rule: generator and checker scripts live in `tools/` and are committed. Never leave one only in a session scratchpad** (that is how the original `words.tsv` and kanji generators were lost). Downloaded source data goes in `tools/cache/`, which is gitignored.
- Pin every source (a commit hash or release tag in the script), so reruns are reproducible.
- Source data the tools read is committed in `sources/` (with attribution in `sources/README.md`): the JLPT N5/N4 CSVs as-is, and `jmdict-subset.json`, only the JMdict entries for words in `words.tsv`/`verbs.tsv` (the full JMdict is 11 MB zipped). JMdict is CC BY-SA 4.0, so the subset stays CC BY-SA with EDRDG attribution; don't drop the notices. After adding rows to either `.tsv`, run `python3 tools/check_data.py --refresh` to rebuild `sources/`; without it the checker falls back to downloading the full JMdict and says so.
- The `.tsv` files are the source of truth: they carry hand edits no generator reproduces. Tools check them or propose new rows; they never overwrite a `.tsv` wholesale.
- `tools/mark_readings.py` sets the bold `*` reading in both kanji files (dry run by default, `--write` to apply). It reimplements the lost generator's WaniKani rule (via kanji-data, pinned commit) and fixes its bug: where WaniKani teaches none of a kanji's on'yomi (all `!` in kanji-data), the original bolded the first-listed one, which is arbitrary (読 トウ, 夏 ゲ); now the on'yomi used by the most common JMdict words wins (JmdictFurigana). On 2026-11-06 it changed 6 lines (読 頭 色 夏 on, 終 帯 kun), and 夏's example became 夏季 by hand. **WaniKani is retained by the user's choice (2026-11-06) but should be replaced if a better openly licensed alternative turns up, and must be before any paid use** (WaniKani content is proprietary; kanji-data's MIT licence can't cover it). A pure word-frequency rule was tested and is worse for kun'yomi (上 あ(げる), 入 い(る)). It also marks the readings learned words use (see `kanji_top1000.tsv` above); rerun it with `--write` after adding words or a verb section. (Ledger kanji cards used to be skipped by `--seed-kanji`; since their conversion on 2026-11-06 it updates all 1,017.)
- `tools/add_radicals.py` sets the kanji files' `radical` column and `verbs.tsv`'s `radicals` column, and appends any missing form to `radicals.tsv` (blank name, Unicode meaning; dry run by default, `--write` to apply). It never changes existing `radicals.tsv` rows except their derived kanji count. Same pinned jmdict-simplified release as `check_data.py`.
- `tools/add_parts.py` (2026-11-25) sets the kanji files' 10th column `parts` (space-separated components, e.g. 読 `言 売`) from KanjiVG's top-level elements (release pinned in `KANJIVG_TAG`), marks the sound part (KanjiVG `kvg:phon`) with a leading `~` (読 `言 ~売`), and appends any part that is neither a radical form nor a Core Kanji to `parts.tsv` with KANJIDIC2's first meaning and main on/kun readings in hiragana (it only fills blank cells, never changes filled ones). Radical-supplement characters become their ordinary form (⻌ → 辶, 飠 → 食 as on the radical line); parts no common font has (𠂊, ⺍, CDP stand-ins) are replaced by their own sub-parts or dropped. Dry run by default, `--write` to apply. Rerun it after adding kanji rows (with add_radicals).
- **Consistency across decks** (user, 2026-11-11): every deck, and any future subdeck, uses the same meaning style as the Core Kanji cards, and a word on two decks must agree. Word meanings: a short comma list, the common sense first, short usage tags only where they matter (`(my)`, `(polite)`, `(weather)`, `(with neg.)`), ` / ` between unrelated homonyms, and etymology, examples and grammar in the `note` column. `tools/clean_meanings.py` applied this to 277 fields of `words.tsv` on 2026-11-11, also fixing wrong glosses (あちら "this way", 口 "job opening", 厚い "kind", バス "bath; bass") and 勉強する's kana. `tools/dedupe_readings.py` removed 33 duplicate readings from the kanji files, where KANJIDIC2 lists a reading with and without okurigana marks (行 -い(き) and -いき); a bold reading is kept over a plain one. Both are dry run by default, and `--write` applies.
- `tools/readable_sentences.py` (read-only, needs Anki open; added 2026-11-14, user's request, as the first step toward example sentences) checks the ~148,000 indexed Tatoeba sentences (CC BY 2.0 FR, via EDRDG's weekly `examples.utf.gz`, pinned by SHA-256 since the export has no versions) against studied Words/Verbs cards and studied Core Kanji. Particles and the copula (`GRAMMAR`) need no card; a word matches by Front, by kana when the sentence writes it in kana (何処{どこ}), or by reading for kana-only words. It reports readable sentences, sentences one new word away and the words that unlock the most, and writes them to `tools/cache/readable_sentences.tsv`. On 2026-11-14 (counting words taught by studied kanji cards, like 私): 348 readable, 215 more pending a kanji, 5,333 one word away; top unlocks 彼 彼女 あなた 好き ください. Sentences that go on cards must keep their Tatoeba ids, with CC BY attribution in `sources/README.md`. Tatoeba's quality varies (the old Tanaka sentences were student translations), so pick by hand.
- `tools/check_drift.py` (read-only; Anki open) rebuilds every deck from the TSVs into an in-memory fake AnkiConnect and compares it note by note with the real collection: every Anki card must be one a seed builds, with the same Back, deck and `ref::`/`topic_` tags. Look-alikes (dynamic), fast-lane placement and `--order` tags are not drift. Exit status 1 on drift. The `sync` skill runs it after every sync (user's rule, 2026-11-14: Anki cards must all have a TSV counterpart, so no drift). First run: no drift across 2,854 cards, after merging 8 Anki-only Words cards (緑 雪 隣 窓 卵 歯 靴 塩) into their Core Kanji cards, keeping their reviews.
- `tools/progress.py` (read-only; Anki open) is the progress report Anki's stats can't give (user's request, 2026-11-14): JLPT N5/N4 coverage of words and kanji (seen / mature), how many of the 100/300/1000 most common deck words are seen (frequency from `tools/cache/examples.utf.gz`; that section is skipped without it), cards seen per `ref::` source, 7-day retention of young/mature reviews, and new-N5 pace with a finish estimate. A one-kanji word counts through its Core Kanji card; lane cards count for their home deck. Each section is one function listed in `SECTIONS` returning (lines, metrics), so add a metric by adding a function. `--record` saves the metrics to `study/progress.tsv` (long format: `date`, `metric`, `value`; a rerun replaces only that day's rows), so progress is data that can be charted. The `sync` skill runs it with `--record` last.
- `tools/check_data.py` (read-only) checks `words.tsv` (each row's `type` against JMdict's part of speech for the best-matching entry, preferring usually-kana entries for kana-only words; levelled rows against the JLPT N5/N4 lists) and `verbs.tsv` (each `group` against JMdict; a する-verb like 勉強する or 世話をする is checked by its noun, which must take する, `vs`). Exit status 1 if anything is flagged. Run it after editing either file: `python3 tools/check_data.py`. It needs no network while `sources/` covers every row. After those fixes it flagged nothing (2026-11-06).

There are no tests, no packaging and no `requirements.txt`. The only third-party dependency is `python-dotenv`. HTTP goes through `urllib`.
- `tools/default_order.py` (added 2026-11-17, user's request: one default order anyone can start from, without touching the user's progress) writes `default_order.tsv`, the fixed study order for the planned starter deck (`docs/n3-plan.md`). It reads only the data files, never Anki. Stages: kana, N5, N4, N3, unlevelled, N2, N1, kanji with no level. In a stage, Words/Verbs/Numbers are interleaved by count, each preceded by the Core Kanji it needs that haven't come yet; then the stage's remaining kanji by frequency; a sentence follows its last word, a look-alike pair its second kanji. The unlevelled words that open `words.tsv` (greetings, 日本) count as N5. `default_order.tsv` is generated: don't hand-edit it, rerun the tool after changing data. The user's own decks keep `main.py --order`. Dry run by default; `--write` saves.
